# 四来源整合与统一设计路线图

> 状态：实施基线
> 日期：2026-08-04
> 适用范围：桌面信息、Dock、分组盒和任务栏外观能力收敛到冰蓝桌面

## 1. 产品决策

冰蓝桌面不是“把四个软件都做成 Pogget 风格”，也不是把四套界面原样拼在一起。正确方法是：

1. 每个来源只负责它擅长的产品语义；
2. 冰蓝桌面统一材质、字体、颜色、间距、动效、焦点和设置入口；
3. 不同模块保留适合其任务的界面骨架，不强行套用同一个“大标题栏 + 玻璃盒”；
4. 借鉴公开行为，不复制不兼容许可证的代码、图标、皮肤或资产。

一句话原则：**统一设计语言，不统一成同一种容器。**

## 2. 四个来源的职责边界

| 模块 | 行为来源 | 保留的核心 | 冰蓝表达 | 明确不做 |
| --- | --- | --- | --- | --- |
| 桌面信息、天气、时间、性能 | 既有桌面信息体验 | 一眼可读、信息层级、独立信息块、低操作干扰 | 锁定时弱化或隐藏标题操作区，时间作为视觉锚点，天气和性能作为次级信息 | 第三方皮肤兼容、INI、脚本或通用 Meter/Measure 引擎 |
| 桌面分组盒 | Pogget | 容器、路径映射、图标网格、分类和缺失提示 | 保留清晰标题、添加、自动整理、排序和映射状态 | 把 Pogget 容器骨架套到所有组件；默认移动、删除或重命名原文件 |
| 应用 Dock | Nexus | 固定与运行应用、窗口分组、启动/切换、运行指示、智能隐藏 | 居中、内容宽度、图标优先的冰蓝 Dock；轻量悬停放大和分组浮层 | 模拟开始菜单、托盘、通知中心；重型反射、粒子或 Shell 替换 |
| 原生任务栏外观 | TranslucentTB | 默认、透明/模糊、动态状态和可恢复性 | 独立的任务栏策略适配器；失败立即回退系统默认 | 改写 Explorer 按钮结构、DLL 注入、把原生任务栏本体改成 macOS Dock |

既有桌面信息体验强调可独立摆放的低干扰信息块；Dock 的功能核心是应用访问、运行应用分组、多显示器和每显示器 DPI；任务栏模块的核心是原生任务栏外观状态。实现时只采纳产品行为，不复制第三方代码或资产。参考：[Winstep Nexus 官方功能](https://www.winstep.net/nexus.asp)、[TranslucentTB 官方仓库](https://github.com/TranslucentTB/TranslucentTB)。DWM 私有适配、材质分层和故障恢复的研究结论见 [`DWMBLURGLASS-UPSTREAM-STUDY.md`](./DWMBLURGLASS-UPSTREAM-STUDY.md)。

## 3. 冰蓝统一设计系统

统一发生在以下层级：

- **材质**：同一套冰蓝背景、边框、阴影和无模糊回退；壁纸变化时仍保证文字对比度。
- **文字**：统一 Display、Title、Metric、Body、Caption 五种语义字号；用户的白色、黑色和自定义文字色继续有效。
- **节奏**：以 8 DIP 为基础间距，控件触达区域不小于 32 DIP；内容密度由组件任务决定。
- **形状**：使用同一组圆角级别，不要求信息块、分组盒和 Dock 使用同一个外轮廓。
- **动效**：短、轻、可关闭，并遵循系统减少动画偏好。
- **编辑状态**：锁定态优先展示内容；编辑态才常驻拖动、设置、添加、关闭等操作。
- **可访问性**：键盘焦点、浅色壁纸回退、玻璃不可用回退和高缩放可读性使用同一规则。

### 3.1 四种表面骨架

1. **环境信息表面**：时间、日期、天气、性能；锁定时不显示厚重标题栏，信息本身构成视觉层级。
2. **工作表面**：待办和普通便签；操作围绕输入、完成和正文，不让拖动区域抢占编辑。
3. **容器表面**：桌面分组盒；标题和整理操作始终有清晰位置，因为“这是哪个盒子、如何添加”是主要任务。
4. **系统导航表面**：Dock；图标优先、居中、内容宽度，运行状态和活动窗口反馈不能依赖文字标签。

## 4. “任务栏苹果化”的产品定义

“苹果化”作为一个组合预设提供，不改造 Windows 原生任务栏内部结构：

| 预设 | Dock | 原生任务栏 | 适用场景 |
| --- | --- | --- | --- |
| Windows 原生 | 关闭 | 系统默认 | 最稳妥、最低干预 |
| 冰蓝混合 | 开启 | 透明/模糊 | 同时保留任务栏按钮和冰蓝 Dock |
| 苹果式桌面 | 开启，居中悬浮 | 智能隐藏，必要时透明过渡 | 用 Dock 完成启动与切换，边缘唤出原生任务栏使用开始菜单和托盘 |

这一路线避免把 Explorer 当作可随意修改的 UI 宿主。Dock 的占用工作区模式使用 Windows AppBar 协议；微软要求 AppBar 注册、响应位置/全屏变化并在销毁前注销，现有阶段 0 实验已沿用该边界。参考：[Microsoft AppBar 文档](https://learn.microsoft.com/en-us/windows/win32/shell/application-desktop-toolbars)。

## 5. 统一设置中心结构

设置中心最终按用户任务而不是按四个来源软件分组：

1. **主题**：主题预设、颜色、字体、材质和文字对比度；
2. **布局**：编辑/锁定、显示器、缩放、恢复默认布局；
3. **桌面组件**：信息、待办、便签和分组盒的内容设置；
4. **Dock**：应用、位置、尺寸、运行状态、悬停效果和智能隐藏；
5. **任务栏**：默认、透明/模糊、智能隐藏和恢复；
6. **隐私与性能**：天气网络说明、采样频率、减少动画和低性能模式；
7. **备份与导入**：主题与个人状态分开处理。

普通用户不需要知道某个功能最初参考了哪款第三方工具。

## 6. 实施波次与验收门

### 波次 A：先纠正视觉母版

目标：建立统一令牌，并把桌面信息从通用容器改为低干扰的信息表面。

- 先产出桌面信息、分组盒和 Dock 的同屏视觉目标，再开始生产 UI 修改；
- 锁定态隐藏信息组件厚标题操作区，编辑态仍可发现拖动、设置和关闭；
- 复用现有天气、性能和状态服务，不重写业务逻辑；
- 验证 100%、125%、150% 缩放、浅/深壁纸、白/黑/自定义文字色和底部内容不截断。

退出标准：用户一眼能区分信息组件和分组盒的用途，但能明确看出它们属于同一套冰蓝主题。

### 波次 B：统一布局与设置

目标：让编辑状态、锁定状态和四来源设置进入同一产品结构。

- 增加全局布局编辑入口和清晰的锁定反馈；
- 设置中心按第 5 节的信息架构扩展；
- 主题令牌、个人内容和运行缓存继续分离；
- 所有新增状态由主分支统一做 Schema 迁移。

退出标准：普通用户不通过组件右键菜单也能找到主题、布局、Dock 和任务栏设置。

### 波次 C：完成 Dock 兼容门，再做生产 Dock

目标：从技术验证进入可替代 Nexus 的产品 Dock。

- 兼容门按开发机实际硬件收缩：本机显示器配置、Explorer 重启、最大化/全屏回避和日常应用清单实测；真实多显示器与混合 DPI 矩阵推迟到具备对应环境时补充；
- 收缩后的矩阵通过后即可把窗口跟踪和 AppBar 接口迁入 `BingLan.App`；
- 生产 UI 首版只做底边居中的图标轨道，含固定/运行合并、运行点、活动指示和窗口分组浮层；上、左、右边缘为后续扩展；
- 悬停放大是可关闭的轻量效果，不作为识别应用的唯一手段，不进验收门。

退出标准：一个普通工作日可以不启动 Nexus，且最大化、全屏、多屏和 Explorer 重启不造成遮挡或工作区残留。

### 波次 D：独立任务栏适配器

目标：替代 TranslucentTB，同时将风险隔离在任务栏模块内。

- 只提供系统默认、透明/模糊、智能隐藏三种静态策略；不做窗口状态联动样式、每显示器独立样式和任意自定义颜色；
- 实现按风险分级：智能隐藏优先使用文档化 AppBar API；透明/模糊使用按 Windows Build 门控的非注入后端，连续失败时熔断恢复；
- 开启前记录原状态，退出、异常恢复和卸载时恢复；
- Windows 版本或 Explorer 状态不支持时立即回退系统默认；
- 不向 Explorer 注入 DLL，不让任务栏故障影响组件和 Dock。

退出标准：关闭 TranslucentTB 后满足外观目标；停用或退出冰蓝桌面后原生任务栏恢复。

### 波次 E：组合预设与分发

目标：把四个模块变成一键可安装、可恢复、可分享的产品。

- 提供 Windows 原生、冰蓝混合、苹果式桌面三个预设；
- 主题导出不携带姓名、城市、待办、文件路径和密钥；
- 验证安装、升级、卸载、开机启动和朋友首次使用流程。

退出标准：没有开发环境的用户可在 5 分钟内完成配置，并能一键恢复系统默认外观。

## 7. 分支与文件所有权

| 分支建议 | 任务 | 可修改范围 | 禁止范围 |
| --- | --- | --- | --- |
| `main`（已完成） | 信息组件视觉目标与信息专属 XAML | `InformationWidgetWindow*`、信息专属设计证据/测试 | `AppState`、共享窗口基类、Dock/任务栏 |
| `spike/dock-compat-matrix` | 补齐阶段 0 真机矩阵 | `design-lab/BingLan.DockSpike/**` | 正式应用状态和设置 |
| `spike/taskbar-adapter` | 任务栏能力与恢复验证 | 新的隔离 `design-lab` 实验及文档 | Explorer 注入、正式应用接线 |
| `main` | 设计令牌、共享窗口基类、状态迁移、设置、正式集成和质检 | 共享保护区 | 不在兼容门前合并高风险模块 |

各分支不得并发修改 `App.xaml`、`WidgetWindowBase.cs`、`AppState.cs`、`LocalStateStore.cs`、`WidgetCoordinator.cs` 或 `SettingsWindow*`；这些共享文件由主分支集中接线。

## 8. 当前判断

- 桌面信息已拆为低容器感的独立表面，锁定/普通态无厚标题操作区，裸文字白色默认与对比度暗影已落地（证据见 [`design-lab/audit/information-surface-2026-08-07/AUDIT.md`](../design-lab/audit/information-surface-2026-08-07/AUDIT.md)）；波次 A 的桌面信息 P0 已解除，剩余为多缩放与复杂壁纸的真机轮换验证。
- 波次 B 的桌面组件主体已经完成：设置中心可统一管理布局预设，以及时间日期、问候、天气、性能、待办、便签和分组盒的显示、锁定、尺寸与外观。Dock、任务栏、隐私与性能、备份与导入仍是明确占位页，不得把占位说明视为功能已接入。
- Dock 已有窗口跟踪和 AppBar 技术证据，但 UI 仍是诊断工具；先过兼容门，不直接美化实验窗口当成生产 Dock。
- 正式应用中尚无任务栏外观模块；波次 D 不应与 Dock 生产接线混成一次改动。

现场截图与逐项问题见 [`design-lab/audit/four-source-product-2026-08-04/AUDIT.md`](../design-lab/audit/four-source-product-2026-08-04/AUDIT.md)。
